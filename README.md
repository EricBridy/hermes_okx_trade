# hermes_okx_trade

OKX 永续合约自动化交易系统

## 当前版本：v7.0 — 候选队列动态管理

基于 **候选队列实时排序 + 持仓动态评分 + 多重噪音过滤** 的智能交易系统，针对 OKX USDT-SWAP 永续合约市场。系统全量扫描 300+ 个合约品种，通过统一候选队列管理开仓、换仓、持仓决策。

## 核心架构

```
┌─────────────────────────────────────────────────┐
│              候选队列（实时更新）                   │
│  通道A(FR反向) + 通道B(动量评分) → 归一化0-100分   │
│  按分数降序排列，每30秒刷新                        │
└─────────────┬───────────────────┬───────────────┘
              │                   │
         有空位?               满仓?
              │                   │
         直接开Top N        候选Top1 vs 持仓最差
                              差值≥10分? → 换仓
                              差值<10分? → 持有不动
              │                   │
┌─────────────┴───────────────────┴───────────────┐
│              持仓（每轮重新评分）                    │
│  recalc_position_score() 每30秒重评               │
│  FR消失/方向反转/动量衰减 → 评分归零               │
│  通道A/B标记来源，评分公式不同                     │
└─────────────────────────────────────────────────┘
```

## 核心特性

- **候选队列管理**：通道A/B归一化到0-100分，统一排序，取Top2持有
- **持仓动态评分**：每轮重评持仓score，FR消失/方向反转→归零触发换仓
- **换仓阈值保护**：候选比持仓高10分才换仓（覆盖手续费成本）
- **8重噪音过滤**：一票否决机制，消除假突破/瀑布/接盘风险
- **追踪止损**：浮盈1.5%后激活，最高点回撤0.8%自动平仓锁利
- **紧急止盈**：浮盈达6%立即落袋，防暴涨后回撤
- **链上数据整合**：Binance Web3 API（6维度：聪明钱信号、热门话题、资金流入、社交情绪、鲸鱼持仓、持仓集中度），60秒实时刷新
- **裸仓保护**：每轮验证所有持仓都有TP/SL挂单，无挂单则强制平仓

## 策略逻辑

### 通道A：极端FR反向（复盘验证唯一稳定盈利）

| 条件 | 阈值 | 说明 |
|------|------|------|
| 资金费率 | \|FR\| > 0.05% | 极端费率 = 散户集中方向 |
| 方向 | 只做FR<0做多 | 复盘：FR<0做多赚$7.66，FR>0做空全亏 |
| 放量 | > 均量130% | 确认主力行动 |
| 仓位 | 90% | 高确信度信号，重仓 |

**逻辑**：FR极端负 = 散户集中做空 → 主力拉盘爆空 → 做多跟随

### 通道B：动量顺势评分（不依赖FR，靠短期行情）

| 评分要素 | 分值 | 说明 |
|----------|------|------|
| 5m涨跌幅度 | 1-3分 | >0.5%=1, >1%=2, >2%=3 |
| 1m放量倍数 | 1-3分 | >1.5x=1, >2x=2, >3x=3 |
| 1m趋势一致性 | 1-2分 | 连涨/跌>10根=1, >12根=2 |
| 链上信号 | 0-12分 | 聪明钱买=+2, 热门话题=+2, 资金流入=+2, 社交情绪=+1~2, 鲸鱼持仓=+1~2, 持仓集中度=+1~2 |
| FR方向一致 | +1分 | FR与趋势同向 |
| 15m趋势强度 | +1分 | 5m和15m同向加分 |
| 5m连续确认 | +1分 | 最近2根5m同向加分 |

- **触发**：综合评分 ≥ 5（满分23，含6个链上因子）
- **方向**：顺势（涨做多，跌做空）
- **仓位**：60%

### 8重噪音过滤（一票否决）

任何一条触发 → score直接归零 → 不开仓/持仓评分归零

| # | 过滤器 | 否决场景 | 瀑布防护路径 |
|---|--------|----------|-------------|
| 1 | 15m趋势冲突 | 5m涨但15m跌 → 不做多 | 中期趋势已反转 |
| 2 | RSI>70超买 | 超买区做多 → 否决 | 涨到极端区域 |
| 3 | RSI<30超卖 | 超卖区做空 → 否决 | 跌到极端区域 |
| 4 | 1m反转检测 | 做多时3根1m全阴 → 正在反转 | 短线已掉头 |
| 5 | **动量衰减** | 3根5m涨跌幅递减 → 势头已消 | 涨不动了 |
| 6 | **量价背离(顶)** | 做多时价涨量缩 → 假突破 | 拉升没量 |
| 7 | **量价背离(底)** | 做空时价跌量缩 → 假跌破 | 砸盘没量 |
| 8 | 方向反转(持仓) | 持仓5m已转跌 → 评分归零 | 趋势已变 |

### 持仓管理

| 机制 | 阈值 | 说明 |
|------|------|------|
| 追踪止损 | 激活1.5%, 距离0.8% | 锁住利润，不坐电梯 |
| 紧急止盈 | 6% | 暴涨时立即落袋 |
| 时间止损 | 15分钟 | 横盘<0.3%则砍仓释放资金 |
| 连亏暂停 | 3次连亏 → 暂停30分钟 | 保护本金 |
| 品种冷却 | 同一品种20分钟内不重复开仓 | 避免过度交易 |
| 换仓阈值 | 候选比持仓高10分(0-100) | 覆盖手续费才换 |

### 仓位动态分配

- **有空位**：按权重分配余额（通道A:1.5, 通道B:1.0）
- **满仓时**：候选Top1 vs 持仓最差，差值≥10分才换仓
- **持仓评分动态**：每30秒重新评分，FR消失/方向反转→评分归零

| 通道 | 权重 | 示例($16余额) |
|------|------|---------------|
| 通道A | 1.5 | ~57% = $9.12 |
| 通道B | 1.0 | ~38% = $6.08 |

单仓模式时保持原始比例（通道A 90%，通道B 60%）。

## 参数配置

```
# 基础
LEVERAGE = 6
TP_PCT = 0.03          # 止盈 3%
SL_PCT = 0.015         # 止损 1.5%
TRAIL_ACTIVATE = 0.015  # 追踪止损激活 1.5%
TRAIL_DISTANCE = 0.008  # 追踪距离 0.8%
TIME_STOP_SEC = 900     # 时间止损 15分钟
SCAN_INTERVAL = 30      # 扫描间隔 30秒
COOLDOWN_SEC = 1200     # 品种冷却 20分钟
MAX_CONCURRENT = 2      # 持有候选队列Top 2（动态）
SWAP_THRESHOLD = 10     # 换仓阈值：候选比持仓高10分才换

# 通道A
FR_EXTREME_THRESHOLD = 0.0005   # |FR| > 0.05%
FR_MAX_THRESHOLD = 0.01         # |FR| > 1% 跳过
CHANNEL_A_VOL_SPIKE = 1.3       # 放量 1.3x
CHANNEL_A_POSITION_PCT = 0.90   # 仓位 90%

# 通道B
MOMENTUM_SCORE_THRESHOLD = 5    # 评分 ≥ 5
CHANNEL_B_POSITION_PCT = 0.60   # 仓位 60%

# 共用
MIN_24H_VOL = 2000000           # 最小24h成交量 $200万
OKX_TAKER_FEE = 0.0005          # 0.05% taker
CHAIN_DATA_TTL = 60             # 链上数据刷新 60秒（Binance Web3，非OKX API）
CHAIN_API_TIMEOUT = 3           # 链上API超时 3秒
```

## 运行环境

- **Python 3.8+**
- **依赖**：requests（无额外依赖）
- **交易所**：OKX（需 API Key + Secret + Passphrase）
- **服务器**：轻量级，2 核 2G 即可

## 快速开始

### 1. 配置 OKX API

创建 `~/.okx/config.toml`：

```toml
[default]
api_key = "YOUR_API_KEY"
secret_key = "YOUR_SECRET_KEY"
passphrase = "YOUR_PASSPHRASE"
```

### 2. 运行

```bash
python3 v7_yao_hunter.py
```

### 3. 查看日志

```bash
tail -f ~/.hermes/scripts/v7_trades.log
```

### 4. 停止

发送 Ctrl+C 或 `pkill -f v7_yao_hunter`
